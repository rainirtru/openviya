# Требования к бэкенду OpenViya

Согласованные требования первой версии по результатам обсуждения Q1–Q55. Реализация еще не начата; параметры реальных подключений и детали реализации проверяются на соответствующих этапах.

## Назначение и границы

- OpenViya — коммерческий VPN-сервис. Общая директория проекта содержит самостоятельные модули; бэкенд находится в `openviya-backend`.
- Бэкенд разрабатывается на Java и Spring и связывает пользовательские каналы с центрами управления VPN-инфраструктурой.
- Сервер бэкенда — отдельный сервер на Ubuntu 26.04. На нем не размещается 3x-ui; основной центр управления и VPN-ноды находятся на других серверах. Дистрибутив каждой ноды выбирается независимо и не обязан совпадать с ОС бэкенда. Размещение уточнено пользователем 15.10.2026.
- Первый пользовательский канал — Telegram-бот. Также нужны собственные веб-кабинеты OpenViya для пользователей и администрации; интерфейсы реализуются отдельными модулями после бэкенда.
- Первый центр управления — основной 3x-ui, управляющий VPN-нодами 3x-ui. Основа должна позволять подключать другие центры управления.
- Сроки, статус подписки и лимиты OpenViya являются источником коммерческих правил. Ручные расхождения в 3x-ui фиксируются и исправляются при синхронизации; фактические устройства и состояние нод получаются из панели.
- Подписка дает доступ ко всем доступным нодам. Ноды могут становиться недоступными, восстанавливаться и добавляться; бэкенд не выбирает одну ноду вместо доступа ко всем.
- Начальный рынок — Россия, расчеты в RUB. Ориентир запуска — 50 пользователей и 4–5 локаций.
- Принято одно Spring-приложение с одной PostgreSQL-базой, внутренними модулями по обязанностям и отдельными адаптерами внешних систем. Подробности — в [архитектуре](architecture.md) и [ADR-0001](adr/0001-modular-monolith.md).

## Техническая основа

- Java 25 LTS и Spring Boot 4.1.1.
- Maven Wrapper с фиксированной версией сборщика внутри проекта.
- PostgreSQL с миграциями схемы.
- REST API для Telegram-бота, пользовательского и административного кабинетов.
- Фоновые операции сохраняют состояние в PostgreSQL и продолжаются после перезапуска: выдача доступа, синхронизация, уведомления и повторные попытки.
- Docker Compose для совместного запуска бэкенда и базы.
- Docker Compose — предусмотренный текущим планом способ запуска, а не требование интеграции с 3x-ui. Нативный production-запуск JAR через systemd с PostgreSQL без Docker технически возможен; замена способа production-развертывания пока не согласована.
- Проверки начисления времени, скидок, резервирования купонов, возвратов, повторных платежных уведомлений и полномочий сотрудников входят в реализацию.

## Подписки и пробный доступ

- У пользователя одна подписка.
- Проект запускается с новыми пользователями; импорт существующих подписок 3x-ui в первую версию не входит.
- Первая реализация продает только доступ на период: 7, 30, 90, 180 или 365 суток.
- Последующее расширение включает уровни подписки с дополнительными возможностями, например AmneziaWG, и отдельную покупку пакетов трафика.
- Цены периодов настраиваются через административный кабинет. Предложение доступно для покупки только после назначения цены и включения администратором.
- Скидка на первую покупку задается настраиваемым процентом. Пробный доступ и неудачные оплаты ее не расходуют; возврат первой покупки не восстанавливает право на скидку.
- Купоны первоначально процентные, включая 100% для розыгрышей. Заказ со скидкой 100% оформляется без создания платежной ссылки.
- Применяется одна наиболее выгодная скидка; скидки не складываются. Купон, который не был применен, не расходуется.
- Для купона задаются срок действия, общий лимит использований, одно использование на пользователя, разрешенные периоды и возможность отключения администратором.
- Бесплатный заказ по купону дает обычную подписку с лимитом 5 устройств. Период добавляется по общим правилам, остаток пробного сохраняется; после такого заказа пробный доступ недоступен, но скидка на первую платную покупку сохраняется.
- При создании подарочного промо администратор задает один из периодов: 7, 30, 90, 180 или 365 суток. Пользователь получает установленный в промо период.
- Примененный купон резервируется при создании заказа. При отмене или истечении неоплаченного заказа резерв освобождается. Использование окончательно учитывается при подтверждении оплаты либо бесплатного заказа; задержка выдачи доступа не освобождает купон.
- Продление действующей подписки прибавляет оплаченный период к ее окончанию.
- Продление выполняется по ручной покупке следующего периода; после подтверждения оплаты срок увеличивается автоматически. На первом этапе не предусматриваются регулярные автоматические списания.
- При возобновлении истекшей подписки сохраняются ссылка подписки и зарегистрированные устройства. Новый период начинается после успешного восстановления доступа.
- Доступ отключается сразу по окончании периода; учетная запись, ссылка и зарегистрированные устройства сохраняются для возобновления.
- Пробный доступ длится 24 часа и доступен один раз на Telegram ID, только до первой покупки.
- Для получения пробного доступа учетная запись должна быть связана с Telegram. При регистрации через будущий сайт потребуется привязка Telegram.
- При покупке во время пробного периода оставшееся время сохраняется. Лимит устройств сразу увеличивается до платного; ссылка подписки и зарегистрированные устройства сохраняются.

## Устройства

- Личная платная подписка первоначально допускает 5 устройств, пробный доступ — 2.
- В будущем увеличение лимита зависит от уровня подписки.
- Бэкенд управляет встроенными HWID- и IP-лимитами 3x-ui. IP-лимит по умолчанию отключен: пользователь может менять сети.
- Пользовательское приложение должно передавать HWID. Первое основное приложение — Happ, включая мобильные и настольные платформы.
- Пользователь самостоятельно освобождает слоты устройств через Telegram-бота: одна операция в сутки на подписку. Поддержка может разрешить дополнительную операцию.

## Оплата и выдача доступа

- Бот предоставляет ссылку на внешний платежный сервис для оплаты в RUB.
- На запуске нужны СБП и карты РФ. В дальнейшем: зарубежные карты, криптовалюта, реферальный баланс и Telegram Stars.
- Предпочтительные кандидаты: Pally (`https://pally.info/`) для СБП и Overpay (`https://overpay.io/`) для карт. Основные API-контракты проверены; параметры конкретных магазинов, hostname API Pally и подключение его API возвратов еще требуют подтверждения. Интеграции должны быть отдельными.
- Для заказа с оплатой создание выполняется только после выбора способа оплаты. При изменении способа создается новый заказ.
- На одну покупку допускается один действующий процесс оплаты. Прежний заказ закрывается перед выдачей новой ссылки там, где это позволяет провайдер; при обрабатываемой оплате или неизвестном результате новая ссылка не выдается до прояснения состояния.
- У пользователя одно незавершенное оформление покупки и 15 минут на оплату. Смена периода или способа заменяет прежний заказ. Если оплата уже обрабатывается, истечение срока требует проверки результата, а не открытия новой оплаты.
- Поздняя подтвержденная оплата замененного заказа учитывается и передается владельцу для возврата. Для одной покупки сохраняется одно начисление периода; деньги не игнорируются из-за локального статуса отмены.
- Период, цена и предоставляемые возможности фиксируются при создании заказа. Изменения каталога действуют на новые заказы.
- Перед выдачей платежной ссылки бэкенд выполняет healthcheck. Нужны работающая управляющая панель и хотя бы одна доступная нода; недоступность части нод не блокирует оплату. Точный состав технических проверок еще не определен.
- После оплаты успешная выдача на доступные ноды запускает период сразу; недоступность части нод не является причиной ждать все ноды.
- Если после оплаты панель или ноды недоступны и выдача не удалась, период начинается после успешной выдачи доступа.
- Через 15 минут задержки выдачи доступа нужно уведомить пользователя и администратора и продолжать попытки. Возврат выполняется по запросу; оплаченное время до выдачи доступа не расходуется.
- Владелец может выполнять полный и частичный возврат с указанием суммы и причины и записью в журнале. Возврат относится к конкретной оплате и не превышает ее невозвращенный остаток. API возвратов Pally включается через поддержку.
- После подтвержденного успешного полного возврата отменяется неиспользованный остаток времени, начисленного конкретным заказом; другие покупки и промо сохраняются.
- Частичный возврат по умолчанию сохраняет срок подписки. Владелец может отдельно указать корректировку времени с причиной; она применяется после подтвержденного успешного возврата.
- Возврат не восстанавливает автоматически использованный купон или право на скидку первой покупки. При необходимости администратор выдает новый одноразовый купон.

## Собственная панель

- Пользователь должен работать через собственный веб-кабинет OpenViya вместо встроенных пользовательских страниц 3x-ui. Выбран обычный веб-интерфейс, не Telegram Mini App.
- Администрации нужна собственная административная панель с уровнями доступа.
- На первом этапе она включает коммерческие операции, подключение центров управления, просмотр состояния нод и управление синхронизацией доступа. Настройка VPN-протоколов, inbound, сертификатов и маршрутизации Xray остается в служебной панели 3x-ui с закрытым публичным доступом; перенос этих функций — отдельный возможный этап.
- В собственной панели нельзя предоставлять вкладку с отдельными VPN-конфигами.
- Подключение к подписке OpenViya предоставляется через Happ crypt5, чтобы скрыть исходную ссылку и ограничить обычный просмотр и экспорт конфигов в интерфейсе Happ.
- Закрытие встроенных страниц 3x-ui должно сохранять возможность получения подписки приложением Happ через OpenViya. Это требование не означает гарантии невозможности извлечь параметры подключения на устройстве пользователя.

## Вход и полномочия

- В первой версии пользователи входят через Telegram. Основа должна позволять впоследствии добавить регистрацию и вход по email.
- Сотрудники используют отдельные административные учетные записи: логин, пароль и обязательная двухфакторная аутентификация.
- Владелец имеет полный доступ, назначает сотрудников и полномочия и выполняет возвраты.
- Администратор управляет пользователями, подписками, тарифами и инфраструктурой.
- Поддержка просматривает состояние пользователя, помогает с подключением и может разрешать дополнительные освобождения слотов устройств.
- Назначение ролей и возвраты первоначально доступны только владельцу.
- Напоминания о платной подписке приходят в Telegram за 3 суток, за 24 часа и при окончании. О пробном доступе — за 3 часа и при окончании.

## Уточняется при реализации и подключении

- Технический состав healthcheck.
- Параметры магазинов Pally и Overpay и эксплуатационная проверка их интеграций.
- Технический контракт публичного маршрута получения подписки и интеграция Happ crypt5.
- Привязка учетных записей при последующем добавлении регистрации по email.
- Дальнейшие эксплуатационные и технические решения.

Порядок реализации и критерии готовности описаны в [плане](implementation-plan.md).
