# Общий OpenViya Ops на домашнем компьютере

## Что подготовлено

Сервер хранит общий реестр, результаты диагностики, данные панелей, Timeweb-токен, SSH-ключи исполнителя и задания в PostgreSQL. Секретные полезные нагрузки зашифрованы AES-GCM отдельным ключом. Windows-приложения обращаются к нему по HTTPS с токеном и закреплённым SHA-256 отпечатком сертификата.

Настройка VPS и изменяющие операции обслуживания выполняются на сервере после принятия задания. Закрытие клиента прекращает наблюдение, а не серверное задание. После прерывания изменяющей операции самим сервером результат может потребовать ручной проверки; такие операции не повторяются вслепую.

Туннели для открытия панели, Windows Terminal и изменение hosts остаются локальными операциями. Для локального SSH каждому устройству нужен свой доступ к VPS и локальное принятие host key. Приватный ключ серверного исполнителя автоматически на ноутбук не загружается.

## На втором компьютере Windows 11

1. Установите Docker Desktop с Linux containers и PowerShell 7. Компьютер должен оставаться включённым, не спать; Docker Desktop должен работать.
2. Закрепите его адрес в DHCP роутера, например `192.168.1.50`. Используйте свой адрес вместо примера.
3. Распакуйте `openviya-ops-lan-server.zip`, например в `C:\OpenViyaOps`. Откройте PowerShell 7:

```powershell
cd C:\OpenViyaOps\ops\lan
.\bootstrap.ps1 -LanBindIp 192.168.1.50
docker compose up -d --build
docker compose ps
```

Скрипт создаст сертификат, токен и ключ шифрования. Он покажет адрес `https://192.168.1.50:8444` и отпечаток сертификата. Для отображения токена выполните:

```powershell
.\bootstrap.ps1 -LanBindIp 192.168.1.50 -ShowToken
```

Обычный повторный запуск сохраняет существующие секреты и сертификат. `-RenewCertificate` предназначен для явной замены сертификата; после неё нужно обновить отпечаток на клиентах.

Разрешите входящий TCP 8444 в Windows Firewall только для доверенных адресов домашней сети и частного профиля сети. Порты PostgreSQL и внутреннего API наружу не публикуются. Проброс порта на роутере не нужен.

## На ПК и ноутбуке

1. Запустите новую сборку `OpenViya.Ops.Desktop.exe`.
2. Откройте настройки хранилища и выберите общий сервер локальной сети.
3. Введите HTTPS-адрес, токен и отпечаток, полученные непосредственно на серверном ПК.
4. Проверьте соединение, сохраните настройку и перезапустите приложение.
5. На исходном ПК используйте перенос локальных профилей. Отдельно выберите, нужно ли скопировать пути/данные панелей, доверенные host keys, приватные SSH-ключи и токен Timeweb. До отправки приложение покажет подтверждение. Локальные оригиналы сохраняются; уже имеющиеся профили сервера не перезаписываются импортом.

Зашифрованные passphrase исходные SSH-ключи автоматический перенос пропускает с сообщением. Их можно использовать при запуске конкретного задания с явным вводом passphrase; параметры принятых заданий зашифрованы на сервере. Для новых VPS исполнитель умеет создавать собственные ключи.

## Резервная копия

Нужны дамп PostgreSQL, папка `.secrets` и `certs` из `ops/lan`. Без исходного ключа шифрования дамп не позволит восстановить сохранённые секреты. Конкретные команды резервного копирования и восстановления — в [README.md](README.md).

## Граница выполненной работы

Код сервера и клиента собирается; комплект подготовлен для запуска на другом ПК. На этом втором компьютере Docker ещё не запущен, перенос реальных данных не выполнялся. Проверка работы двух клиентов и возобновления реального VPS-задания относится к запуску стенда; успешная сборка её не заменяет.
