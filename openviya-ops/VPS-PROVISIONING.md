# Полная настройка нового VPS

Мастер «Настроить новый VPS» предназначен для только что установленного сервера. Существующий сервер добавляйте обычным профилем. Поддерживаются Ubuntu 26.04/24.04 LTS и Debian 12/13 с systemd, amd64 или arm64. Обнаружение установленной панели, существующего администратора или правил доступа останавливает автоматическую установку: мастер не переустанавливает рабочие серверы.

## Что указать

1. Публичный IP VPS, действующий SSH-порт и первоначального пользователя. Обычно это root. Другой пользователь должен иметь sudo без запроса пароля.
2. Начальный доступ: пароль **либо** приватный SSH-ключ с необязательной passphrase. Выбирайте файл без `.pub`, например `C:\Users\raini\.ssh\openviya_vps_ed25519`; `.pub` — публичная часть, она не подходит для входа. Поле административного ключа ниже относится к будущему входу vpsadmin. Одного IP для установки недостаточно.

   Если ключ зашифрован, в поле «Пароль / passphrase» начального доступа введите пароль, заданный при создании этого ключа. PowerShell может успешно подключаться через уже разблокированный SSH-agent, но мастер установки читает выбранный файл через SSH.NET и требует его passphrase отдельно. Этот пароль остаётся только в памяти запуска; в журнал и базу он не записывается. При пустом поле приложение показывает отдельную подсказку о зашифрованном ключе.
3. Регион, индекс и DNS-зону. По умолчанию используется автоматическое создание через настроенный Timeweb API. Для USA-1 получатся `usa-1.openviya.online` и `panel-usa-1.openviya.online`. В ручном режиме создайте записи на сайте DNS-провайдера; мастер только проверит публичный DNS.
4. Email для Let’s Encrypt, имя нового администратора (обычно vpsadmin), порт панели (по умолчанию 38471). Можно выбрать собственный административный Ed25519-ключ или создание отдельного локального ключа.
5. Доступ панели: SSH-туннель по умолчанию или туннель и публичный доступ. Необязательное поле «Разрешённые IP» принимает IPv4/IPv6 по одному адресу на строку, без запятых, масок и названий доменов. При заполненном списке публичный порт панели разрешается только для этих адресов; пустой список означает доступ с любого IP. Для личного VPN укажите его публичный выходной IP. Подтвердите, что сервер свежий, принимаете условия Let’s Encrypt и подготовили firewall провайдера.

Перед отправкой учётных данных мастер сканирует SSH host key. Сверьте SHA-256 fingerprint с консолью провайдера или другим доверенным источником и явно примите его. При изменении IP/SSH-порта доверие надо подтвердить заново. Проверка применяется к SSH и SFTP; изменившийся ключ автоматически не принимается.

## Домены и порты

| Назначение | Имя / порт | Доступ |
| --- | --- | --- |
| SSH | IP VPS, существующий порт (обычно TCP 22) | С компьютера администратора |
| VPN | `usa-1.openviya.online`, TCP 443 | Правило firewall готовится; inbound/client создаётся отдельно |
| Панель | `panel-usa-1.openviya.online`, TCP 38471 | По умолчанию только через SSH-туннель |
| Выпуск и продление сертификата | TCP 80 | Должен быть доступен из интернета для HTTP-01 |
| Локальный туннель панели | TCP 20530–20629 или выбранный свободный | Только 127.0.0.1 на вашем компьютере |

DNS-запись задаёт IP, а порт задаётся приложением или URL. VPN-имя используется клиентами VPN; сертификат панели выпускается для отдельного `panel-…` имени. Для браузера через туннель используется именно домен панели с локальным портом, чтобы сохранить проверку имени сертификата. При необходимости локальную запись hosts добавляет отдельное действие с UAC. Hosts-helper пока поддерживает только `panel-*.openviya.online`.

В firewall панели провайдера заранее разрешите текущий SSH-порт и TCP 80, а для VPN — TCP 443. При публичной панели разрешите также её порт с выбранных адресов. Мастер не управляет firewall провайдера. A/AAAA должны вести на этот VPS; удалите устаревшие записи. Встроенная публичная проверка обращается к Cloudflare DoH, отдельно от локального hosts.

## Порядок выполнения

1. Создаётся локальный профиль и административный ключ. Встроенный `bootstrap-vps.sh` передаётся по SFTP, проверяется SHA-256 и помещается в отдельный каталог root:root с правами 0700. На сервер передаётся только публичная часть административного ключа.
2. Проверяется ОС и состояние VPS. Автоматический режим создаёт отсутствующие DNS-записи через API; ручной не вызывает API. Мастер ждёт готовности публичного DNS до изменения SSH/firewall.
3. `prepare` устанавливает необходимые пакеты и обновления, создаёт администратора и настраивает UFW. На VPS включается независимый 20-минутный таймер восстановления доступа.
4. Приложение устанавливает **новое** SSH-соединение административным ключом и проверяет sudo. Только после этого запускается `finalize`: защита SSH, fail2ban, обновления безопасности, ограничение журналов, Let’s Encrypt HTTP-01, закреплённая версия 3x-ui и резервные копии.
5. После успешного завершения приложение проверяет домен, порт и TLS-режим панели, получает её логин/пароль/путь и сохраняет их через DPAPI. В профиле доступно отдельное окно данных панели; копирование выполняется только по кнопке.

Начальный пароль и passphrase существуют только в памяти текущего запуска. SSH.NET читает приватный ключ локально; приватный ключ не загружается на VPS. Автоматически созданный ключ находится в `%LOCALAPPDATA%/OpenViya/Ops/keys/<server-id>/admin_ed25519` с ограниченными ACL Windows. Он без passphrase: сохраните защищённую копию, иначе можно потерять доступ после поломки компьютера. DPAPI-секреты привязаны к Windows-пользователю и исключены из экспорта профилей.

## Прерывание и продолжение

Во время работы мастер показывает текущий шаг VPS и журнал с локальным временем событий. При ошибке сохраняются этап, распознанный серверный шаг и код завершения. После закрытия мастера откройте «Журнал настройки…» в карточке профиля: просмотр использует только локальную историю. Хранятся последние 200 полученных событий; пропущенные во время отключения или между опросами шаги не выдумываются. Пароли, ключи, путь панели и сырой вывод команд в журнал не попадают.

Новый bootstrap передаёт только разрешённые коды шагов через systemd `StatusText` с `NotifyAccess=all`. Неизвестные строки отбрасываются обеими сторонами протокола. Ранее выпущенный установщик допускается только при точном совпадении закреплённой контрольной суммы; для него доступны общие этапы без подробных подшагов. Другая неизвестная версия по-прежнему блокирует продолжение. Работающий файл на VPS не перезаписывается ради отображения прогресса.

Серверные этапы запускаются отдельными systemd oneshot units с `--no-block`. Закрытие приложения или потеря сети прекращают наблюдение, но не гарантируют остановку задания на VPS. Откройте сохранённый профиль и продолжите тот же запуск; мастер сначала проверит административный вход, состояние этапа и таймер. Повторный `prepare` после ошибки не запускается автоматически.

Если новый вход не работает, `finalize` не запускается. После истечения rollback требуется проверить доступ через консоль провайдера. Если `finalize` завершился ошибкой, сначала устраните причину на сервере по [инструкции bootstrap](../ops/vps/README.md); мастер не сбрасывает защитные механизмы ради повторной установки. Для диагностики серверных units используйте run ID из локального состояния: `openviya-desktop-<run-id-без-дефисов>-prepare.service` и `…-finalize.service`. Журнал может содержать закрытый URL-путь панели; не публикуйте его целиком.

Сценарий не создаёт VPN inbound/client, не подключает ноду к CONTROL и не перезагружает сервер автоматически. Сертификаты и локальные резервные копии обслуживает bootstrap; резервные копии надо отдельно выносить с VPS в защищённое хранилище. Первое применение к реальному VPS проверяйте через доступную консоль провайдера: локальные проверки с подставными сервисами не подтверждают особенности образа конкретного хостера.

## Модули

`Core` задаёт контракты запуска, этапов и временных учётных данных. `Provisioning` выполняет SSH.NET/SFTP с pinning, подготовку ключа и последовательность DNS → prepare → новый SSH → finalize → credentials. `Storage` хранит последнее состояние каждого запуска и шифрует данные панели. `Desktop` предоставляет мастер, продолжение и просмотр данных. Общий bootstrap встроен в сборку как ресурс, а его machine-команды возвращают ограниченный JSON без копирования сырых журналов в интерфейс.
