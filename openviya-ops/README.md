# OpenViya Ops

Локальное Windows-приложение для реестра VPS, SSH-подключений, туннелей и диагностики панелей. Основа — [архитектура приложения](../ops/LOCAL-OPS-APP-ARCHITECTURE.md) и [сетевая схема OpenViya](../ops/NETWORK-PLAN.md).

## Возможности первой версии

В мастере нового VPS для режима «Туннель и публичный доступ» есть необязательное многострочное поле «Разрешённые IP». Вставляйте IPv4/IPv6 по одному на строку без запятых и масок. Пустое поле оставляет публичный порт панели без ограничения по источнику; заполненное разрешает только перечисленные адреса. Для доступа через личный VPN нужен его внешний выходной IP. Это параметр первичной установки: сохранение списка в мастере не перенастраивает уже установленный VPS. Firewall провайдера настраивается отдельно.

- Профили существующих серверов: IP/hostname, роль, регион, SSH identity, VPN-имя, домен/порт панели и локальный порт туннеля.
- Локальная SQLite-база; защищённый путь панели шифруется DPAPI текущего Windows-пользователя.
- Подбор локальных портов, несколько одновременно работающих SSH-туннелей, остановка только принадлежащих приложению процессов.
- Явное принятие SSH host-key fingerprint после независимой проверки; последующие соединения используют строгую проверку. Изменившийся ключ автоматически не заменяется.
- Проверки DNS/TCP/SSH и HTTPS через туннель с обычной проверкой имени/CA, без отключения TLS.
- Открытие панели в обычном браузере, интерактивный SSH-терминал, импорт/экспорт профилей без секретных полей.
- Узкий UAC-helper для локальных записей `panel-*.openviya.online`: резервная копия и сохранение чужих записей. VPN-имена helper не принимает.
- Поддомены Timeweb Cloud: автоматическое создание по API или ручная настройка на сайте провайдера; токен хранится зашифрованным через DPAPI.
- Отдельная проверка публичных A/AAAA и NS через Cloudflare DoH, которая не использует локальную запись hosts для проверяемого имени.
- Полная настройка свежего VPS: начальный вход по паролю или ключу, DNS, защищённый SSH, firewall, Let’s Encrypt, установка 3x-ui и получение данных панели.

Это первая рабочая версия инфраструктурного инструмента. Подключение нод к CONTROL, управление покупателями и deployment Java-бэкенда в неё не входят. Открытие приложения не запускает подключения и не меняет DNS.

Контракт DNS и границы автоматизации описаны в [схеме интеграции Timeweb Cloud](TIMEWEB-DNS-INTEGRATION.md).
Подготовка нового сервера и восстановление прерванной настройки описаны в [руководстве полной настройки VPS](VPS-PROVISIONING.md).

## Общий реестр и задания в домашней сети

OpenViya Ops можно подключить к общему LAN-серверу: там хранятся общие профили и продолжаются долгие задания настройки VPS, даже когда клиентское приложение закрыто. Инструкция по установке Docker-служб на отдельный Windows 11 ПК, резервным копиям и подключению ноутбука находится в [руководстве LAN-развёртывания](../ops/lan/README.md). Для работы сервера этот ПК должен оставаться включённым и не переходить в сон.

## Запуск

Текущая сборка с мастером VPS, журналом настройки и исправлением получения SSH fingerprint находится в `.artifacts/app-vps-progress/OpenViya.Ops.Desktop.exe`. Перед обычным запуском новой версии закройте старую: приложение использует один общий экземпляр и общую локальную базу. Профили сохраняются. Для переноса сохраняйте всю папку `app-vps-progress`, включая `helper`.

Для готовой локальной сборки после `Publish`:

```text
.artifacts/app/OpenViya.Ops.Desktop.exe
```

Для запуска скопированной сборки сохраняйте всю папку `.artifacts/app`, включая подпапку `helper`: это не один независимый exe. Сборка self-contained для Windows x64, установка .NET на целевом компьютере не требуется.

Нужны Windows 11 x64 и установленный **OpenSSH Client**; Windows OpenSSH Server не требуется. Интерактивный SSH открывается через Windows Terminal. Приватный ключ с passphrase предварительно загрузите в ssh-agent либо используйте интерактивный SSH для проверки; автоматический туннель не спрашивает пароль в скрытом окне.

Для разработки нужен .NET 10 SDK. `build.ps1` использует `.tools/dotnet/dotnet.exe`, если такой локальный SDK есть, иначе `dotnet` из PATH:

```powershell
cd openviya-ops
./build.ps1 -Action Build
./build.ps1 -Action Check
./build.ps1 -Action Publish
./build.ps1 -Action Publish -OutputDirectory .artifacts/app-dns
./build.ps1 -Action Publish -OutputDirectory .artifacts/app-vps
./build.ps1 -Action Publish -OutputDirectory .artifacts/app-vps-sshfix
./build.ps1 -Action Publish -OutputDirectory .artifacts/app-vps-progress
./build.ps1 -Action Run
```

Скрипт сборки выключает CLI-телеметрию и создание ASP.NET development certificate для этих запусков. Локальный SDK и результаты сборки игнорируются Git.

## Первый сервер

1. Добавьте профиль: например USA-1, IP американского VPS, VPN_NODE, SSH 22, пользователь vpsadmin и путь к своему SSH identity-файлу. Используйте фактический порт панели: старый 2053 не заменяется автоматически на 38471.
2. Выберите режим поддоменов. Автоматический режим предложит `panel-usa-1.openviya.online` и `usa-1.openviya.online` и создаст отсутствующие записи через настроенный API при сохранении. В ручном режиме создайте записи на сайте провайдера и введите имена самостоятельно. Индивидуальный URL-путь панели задаётся отдельно. Обычные туннели используют системный OpenSSH; приватный ключ на VPS не загружается.
3. Выполните сканирование host key. Сверьте SHA-256 fingerprint с консолью провайдера/доверенным источником и только после этого примите его. Сканирование по сети само по себе не устанавливает доверие.
4. Проверьте SSH и включите туннель. Для локального порта можно оставить автоматический выбор 20530–20629.
5. Проверьте TLS панели. На сервере должен быть действующий сертификат домена панели; старый самоподписанный сертификат без доверия не будет принят. Порядок перехода на Let’s Encrypt — в [инструкции VPS](../ops/vps/README.md).
6. Проверьте hosts. Если корректная ручная запись уже есть, её можно использовать. Для добавления записи кнопкой приложения Windows запросит UAC. Изменяется только домен панели, не VPN-адрес.
7. Откройте панель. URL содержит домен панели и локальный порт туннеля; проверка сертификата остаётся включённой. Вход и 2FA выполняются в браузере.

Профиль APP не получает фиктивную панель 3x-ui: связанные с ней действия недоступны. В ручном режиме сохранение меняет только локальный реестр; в автоматическом — также запускает создание DNS. Для переключения IP/ключа/порта работающего подключения сначала остановите его туннель.

## Автоматические и ручные поддомены

Новые профили используют **автоматический** режим. Укажите зону `openviya.online`, регион и индекс ноды. DNS-адрес можно оставить пустым, если SSH-адрес — публичный IP; если SSH использует hostname, укажите публичный IP отдельно. IPv4 создаёт A-запись, IPv6 — AAAA. SSH hostname не подставляется в A/AAAA и не разрешается неявно в какой-либо адрес.

Перед первым автоматическим сохранением откройте **«Настройки Timeweb DNS…»**, вставьте API-токен, сохраните его и проверьте доступ к зоне. Проверка выполняет только чтение API. Наличие домена у регистратора Timeweb само по себе не подтверждает его доступность в аккаунте Timeweb Cloud. Зона должна обслуживаться поддерживаемыми NS Timeweb; приложение не меняет делегирование.

Кнопка **«Сохранить и создать DNS»** сохраняет профиль и запускает создание отсутствующих поддоменов и записей. Совпадающие записи пропускаются. Чужой IP, CNAME/DNAME или несколько адресных записей вызывают конфликт; автоматической замены и удаления нет. При отсутствии токена профиль сохраняется с сообщением об ожидании настройки. После настройки токена повторите сохранение либо проверьте и примените план DNS на карточке сервера.

**Ручной** режим означает настройку DNS на сайте провайдера. Введите доменные имена в профиль; приложение не создаёт и не меняет их через API. Проверка публичного DNS остаётся отдельным действием и не требует токена Timeweb.

Существующая база версии 1 и старые JSON-профили импортируются в ручном режиме с сохранением имён. Новый экспорт сохраняет выбранный режим, зону и DNS-адрес. Импорт, удаление профиля и запуск приложения не создают DNS-записи. Удаление токена тоже не удаляет записи у провайдера.

Пара VPN/панель не является транзакцией: одна запись может создаться, пока вторая завершится ошибкой. Приложение показывает результаты по именам; повторное действие перечитывает состояние. После потери ответа POST нельзя считать запись ни созданной, ни отсутствующей без сверки. Успешная запись в API и распространение публичного DNS показываются раздельно. Публичная проверка обращается к Cloudflare, передавая проверяемые имена; она не подтверждает исправность VPN или 3x-ui.

Создание DNS не устанавливает сертификат и не открывает порты. DNS не задаёт порт: VPN 443 и панель 38471 остаются отдельными параметрами. Для других зон DNS-клиент пригоден, но hosts-helper по-прежнему ограничен именами `panel-*.openviya.online`.

## Ошибка получения SSH host key на Windows

Некоторые Windows OpenSSH 9.x содержат [ошибку ssh-keyscan](https://github.com/PowerShell/Win32-OpenSSH/issues/2140): `choose_kex: unsupported KEX method sntrup761x25519-sha512@openssh.com`. При этом обычный `ssh` может успешно подключаться. Ops обнаруживает именно эту ошибку и получает публичный host key встроенным SSH.NET-сканером. Соединение намеренно отклоняется на этапе получения ключа, до аутентификации; пароль, приватный ключ и SSH-agent для сканирования не используются. Fingerprint по-прежнему нужно независимо сверить и явно принять.

Исправление проверено на localhost с независимо сгенерированным ключом и на сообщённом проблемном VPS в режиме только сканирования, без входа, команд и изменения доверия. Диагностический режим из каталога `openviya-ops`: `./.tools/dotnet/dotnet.exe run --project tests/IntegrationChecks/IntegrationChecks.csproj -c Release -- --scan-only SERVER_IP`. Это явное сетевое действие, не часть обычного `Check`.

## Ход настройки VPS

Мастер показывает текущий шаг на VPS и раскрывает «Журнал настройки» с временем полученных событий. Видны обновление пакетов, создание администратора, UFW, fail2ban, выпуск сертификата, установка 3x-ui и проверки. При сбое отображаются распознанный шаг, код завершения задания и подсказка по проверке. Общая заглушка об ошибке больше не заменяет причину остановки.

В карточке профиля кнопка «Журнал настройки…» открывает сохранённую историю без подключения к VPS. SQLite хранит до 200 событий каждого запуска; одинаковые последовательные статусы не дублируются. Журнал не входит в экспорт профилей. Его можно выделить и скопировать обычными средствами Windows. Пароли, приватные ключи, закрытый путь панели и сырые серверные журналы в эти события не включаются.

Новый установщик передаёт фиксированные коды шагов через systemd StatusText; приложение опрашивает состояние примерно раз в 3 секунды. Короткие шаги между опросами могут не попасть в историю. Для уже начатого запуска предыдущей поддерживаемой версии сохраняются общие этапы: приложение явно сообщает об ограниченной детализации и не заменяет работающий скрипт на VPS. История до обновления не восстанавливается задним числом.

Проверены ошибки конкретного шага, неизвестные данные протокола, продолжение старой версии, сохранение/повторное открытие и ограничение истории. Общий `Check`, Bash fixtures и готовый exe smoke прошли. Снимки нового интерфейса — `.artifacts/published-progress-smoke.vps-progress-*.png`. Настройка реального VPS для этой проверки не запускалась.

## Данные и доверие

Данные по умолчанию: `%LOCALAPPDATA%/OpenViya/Ops/`. SQLite, отдельный known_hosts и SSH-конфиги приложения не заменяют глобальные файлы пользователя. Для тестового отдельного реестра поддерживается `--data-dir ABSOLUTE_PATH`; импорт не запускает подключения автоматически.

Экспорт исключает SSH identity path, защищённый путь панели, данные входа 3x-ui и API-токен. После переноса профилей на другой компьютер заново выберите ключи, задайте индивидуальные пути панелей, настройте токен и подтвердите host keys. DPAPI-данные не являются переносимым архивом секретов.

Мастер полной настройки использует SSH.NET и читает выбранный приватный ключ в память для аутентификации и получения публичной части. Начальный пароль и passphrase не сохраняются и не передаются аргументами процесса. При автоматическом создании административного ключа он хранится локально с ограниченными Windows ACL; этот файл не зашифрован passphrase и требует отдельной защищённой резервной копии. Логин, пароль и путь панели сохраняются через DPAPI текущего пользователя.

Удаление профиля не удаляет сервер и его данные. Завершение приложения закрывает его SSH-туннели; VPN/Xray, Certbot и серверные backup продолжают работать. Чужие ssh.exe и терминальные сеансы не завершаются.

Hosts-helper пока принимает только `panel-*.openviya.online`. Он сохраняет исходные байты в backup рядом с системным hosts, проверяет неизменность файла перед заменой, сохраняет кодировку/ACL и удаляет только точные помеченные записи OpenViya Ops. Не удаляйте запись, пока она нужна активному туннелю. Разработческая сборка ещё не имеет подписанного installer/update; UAC показывает фактического издателя сборки.

## Проверки

`build.ps1 -Action Check` собирает решение и запускает консольные harness-проверки:

- StorageChecks: валидация, SQLite/DPAPI, отсутствие секретов в экспорте, атомарный импорт и связи CONTROL/нод.
- SshChecks: аргументы/адреса, проверка ключей и pinning, локальное владение процессом/listener и его завершение.
- NetworkChecks: преобразование hosts на тестовых строках, сохранение чужих данных, ограничения доменов/URI.
- DnsChecks: подставной HTTP transport Timeweb, режимы, планирование, конфликты, повторные запросы и частичные/неподтверждённые результаты.
- PublicDnsChecks: подставные ответы Cloudflare DoH, NS/A/AAAA, ошибки JSON/HTTP, отмена и timeout чтения тела.
- ProvisionStorageChecks: шифрование данных панели, состояние запусков, отсутствие секретов в экспорте и повреждённые файлы.
- ProvisioningChecks: полный сценарий на подставных SSH/DNS-сервисах, новый вход администратором до finalize, продолжение и остановка при ошибках.
- ProvisionTransportChecks: реальный SSH/SFTP только на localhost с временными паролем/ключами и проверкой host-key pinning. Для этой проверки нужны Python и `.tools/ssh-fixture` с AsyncSSH 2.24.1 (команда установки ниже).

Нативный UI smoke создаёт отдельный временный реестр, отрисовывает WPF в PNG и не подключается к VPS. Он не меняет системный hosts. Проверка UAC на настоящем системном файле выполняется отдельно по явному действию пользователя.

```powershell
./tests/DesktopChecks/run-smoke.ps1
```

После сборки smoke проверяет создание и редактирование профиля через форму, сохранение выбранного профиля, удаление временной записи из хранилища и отрисовку при 1280×820 и 900×620. Снимки находятся в `.artifacts/ui-smoke*.png`. Это не заменяет ручную проверку клавиатуры, screen reader и UAC.

Для расширенной проверки SSH есть изолированный loopback fixture. Из папки `openviya-ops`, при наличии Python:

```powershell
python -m pip install --target .tools/ssh-fixture asyncssh==2.24.1 bcrypt==5.0.0
./.tools/dotnet/dotnet.exe run --project tests/IntegrationChecks/IntegrationChecks.csproj -- --python-local
```

Если используете системный SDK, замените `./.tools/dotnet/dotnet.exe` на `dotnet`. Fixture генерирует временные ключи, поднимает SSH/HTTP только на `127.0.0.1` и удаляет свои процессы и файлы после проверки. Проверяются принятие fingerprint, key-auth, два одновременных туннеля, повторный запуск, независимая остановка, передача HTTP и отклонение незашифрованного HTTP при запросе HTTPS. Docker и SSH Server Windows не нужны.

При интеграции 16 октября 2026 года сборка Release прошла без предупреждений и ошибок; StorageChecks, SshChecks, NetworkChecks, loopback IntegrationChecks и UI smoke прошли на Windows. Снимки реестра и формы просмотрены; исправлены первоначальная раскладка таблицы, нечитаемый текст выбора роли и обрезанные действия компактной формы.

После добавления DNS повторно прошёл полный `build.ps1 -Action Check`: сборка семи проектов без предупреждений и ошибок, StorageChecks, SshChecks, NetworkChecks, 15 проверок подставного Timeweb API и PublicDnsChecks. WPF smoke проверил автоматический и ручной режимы, отсутствие токена, ошибку ввода зоны и формы 1280×820 / 900×620. Сборка `.artifacts/app-dns` прошла отдельный запуск готового exe на временной базе. Настоящие API-токены и сетевые запросы к Timeweb/Cloudflare в этих проверках не использовались. Проверка в реальном аккаунте ещё необходима.

После добавления полной настройки VPS общий `Check` прошёл для восьми проектов без предупреждений и ошибок, включая все восемь harness-наборов. Оркестрация проверена подставными сервисами: root и начальный пользователь с sudo, DNS, новый административный вход, продолжение, ошибки и отмена. ## Модули

| Проект | Назначение |
| --- | --- |
| Core | Контракты, профили, валидация, доменные имена по ролям |
| Storage | SQLite, DPAPI, импорт/экспорт |
| Ssh | OpenSSH, host trust, SSH-туннели, Windows Job Objects |
| Network | DNS/TCP/TLS, клиент hosts-helper |
| Dns | Ограниченный клиент Timeweb Cloud: проверка зоны, план и создание записей |
| Provisioning | Начальный SSH/SFTP, ключ администратора и оркестрация встроенного bootstrap |
| HostsHelper | Только ограниченная операция с системным hosts через UAC |
| Desktop | Windows-интерфейс и пользовательские сценарии |

В разработке участвовали четыре агента GPT-6 Luna с высоким уровнем рассуждения; интеграционная проверка и сборка выполнялись отдельно.

При HTTP 404 от метода Timeweb name-servers приложение проверяет публичные NS через отдельный запрос Cloudflare DoH без API-токена. Создание разрешено только при подтверждённых NS Timeweb; ошибки прав 401/403 этой проверкой не обходятся. Для свободного номера (например usa-2) автоматически создаются оба имени: usa-2.openviya.online и panel-usa-2.openviya.online. Конфликт существующей записи показывается с именем поддомена; смена IP существующей записи автоматически не выполняется.

TXT/SPF и MX у поддомена совместимы с A/AAAA и сохраняются при автоматическом создании адресной записи, в том числе когда Timeweb добавляет SPF сразу после создания поддомена. Повторный запуск распознаёт совпадающую A/AAAA вместе с TXT/MX и не создаёт дубликат.

## Обслуживание установленного VPS

В карточке сохранённого сервера откройте «Обслуживание VPS…», чтобы по запросу проверить фактические настройки панели, сертификат, резервные копии и версию 3x-ui. Для SSH используется ранее принятый fingerprint и административная учётная запись профиля; пароль или passphrase вводится в маскированное поле и не сохраняется.

Для смены порта, режима доступа или разрешённых IP сначала проверьте состояние и покажите план. Окно перечислит конкретные изменения и отдельно предупредит о публичном доступе и пятиминутном таймере восстановления. Правила firewall у VPS-провайдера остаются ручной настройкой. Сертификат продлевается только после отдельного подтверждения Let’s Encrypt. Архивы можно скачать в выбранную папку; проверка версии 3x-ui не устанавливает обновление.
