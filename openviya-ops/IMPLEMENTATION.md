# Общий контракт реализации

## Сценарии приложения после обновления

- `VpsProvisionWizardViewModel` управляет четырьмя шагами: подключение → параметры сервера → доступ к панели → проверка и установка. `VpsConnectionPreflightService` выполняет только чтение по SSH/SFTP; fingerprint принимается отдельным явным действием. Секреты не сохраняются.
- `PanelOpeningService` объединяет запуск туннеля, явное согласие на hosts/UAC, строгую TLS-проверку и запуск браузера. Публичный режим использует внешний HTTPS и не создаёт SSH-туннель. Решение об удалении hosts основано на типизированном признаке владения, а не тексте сообщения.
- `ServerMaintenanceViewModel` ведёт обслуживание установленного управляемого VPS; `IVpsServerMaintenanceService` исполняет фиксированный протокол. План сверяется с текущими настройками; перед изменениями доступа ставится независимый таймер отката.
- `VpsProgressViewModel` отображает структурированный прогресс, время шага, последний ответ VPS и DNS по именам. Сырые SSH/API-ответы в журнал не передаются. Потеря статуса не вызывает повторный запуск установки.
- Профиль SQLite/JSON версии 3 хранит желаемый режим доступа, способ открытия панели и построчный список IP. `SqliteServerStateStore` хранит отдельно последнее наблюдение с датой проверки. Старые профили мигрируют с режимом туннеля; локальные секреты защищаются прежним механизмом DPAPI.
- Основные действия карточки — открытие панели, SSH и диагностика. Проверки, управление туннелем, DNS/hosts и обслуживание вынесены в отдельные вкладки.

Распределение ответственности: окна собирают ввод и показывают подтверждения; ViewModel управляют состоянием сценариев; сервисы выполняют действия через подставляемые интерфейсы; хранилища отвечают за локальную сохранность. Диагностика, доступность порта, аутентификация SSH, корректность TLS и работа VPN не объявляются одной общей проверкой.

Первая версия OpenViya Ops реализует реестр существующих VPS, SSH trust, туннели, диагностику и открытие панелей. Код на .NET 10/WPF, русский интерфейс. Архитектура: ../ops/LOCAL-OPS-APP-ARCHITECTURE.md.

Core/Contracts.cs — общий контракт, изменения только после согласования с интегратором. Созданные классы адаптеров должны иметь следующие конструкторы:

- Storage.SqliteProfileStore(AppPaths paths) : IProfileStore.
- Ssh.SshService(AppPaths paths) : ISshService.
- Ssh.TunnelManager(SshService ssh) : ITunnelManager.
- Network.DiagnosticsService() : IDiagnosticsService.
- Network.HostsService(AppPaths paths) : IHostsService.

Прикладная проверка профиля: Core.ProfileValidator.Validate(ServerProfile) возвращает IReadOnlyList<string>; Core.ProfileDefaults.Apply(ServerProfile, string baseDomain = "openviya.online") возвращает ServerProfile с предложенными доменами. Валидатор создаёт агент хранения. Никакие фоновые сетевые обращения на настоящие VPS, изменения hosts, доверия или ключей в ходе разработки не выполнять.

UI открывает браузер только после проверки tunnel TLS и hosts. Никаких автоматических TOFU accept, StrictHostKeyChecking=no, localhost TLS bypass, удаления чужих процессов и plaintext secret export. Base path защищается DPAPI в SQLite и исключается из export. Пользователь явно принимает конкретный fingerprint после сверки. Работа с доменом панели не меняет VPN-имя.

Рабочие области: агент хранения — Core (кроме Contracts.cs) и Storage; агент SSH — Ssh; агент диагностики — Network и HostsHelper; агент UI — Desktop, DESIGN.md, UX-CONTRACT.md и premium-ui.json. Интегратор владеет solution, общими контрактами, README, сборкой и сквозными проверками. Не откатывать чужие изменения.

## Установленный управляемый VPS

`Desktop.ServerMaintenanceWindow` собирает ввод, показывает подтверждения и рендерит снимки; `ServerMaintenanceViewModel` управляет асинхронными операциями и локальным сохранением. Remote-действия выполняет `IVpsServerMaintenanceService` через закреплённый ключ профиля. Окно не сканирует SSH host key и не выполняет запросов при открытии. Пароль администратора или passphrase ключа передаётся только в вызов операции и удаляется из PasswordBox после завершения.

Настройки доступа на VPS изменяются только после получения свежего `VpsMaintenancePlan`, явного подтверждения и успешной перепроверки SSH/панели внутри сервиса. При смене панели порта сначала останавливается принадлежащий приложению туннель после отдельного подтверждения. Успешная удалённая настройка записывается в профиль и `ServerObservedState`; если локальная запись не прошла, интерфейс прямо сообщает, что VPS уже изменён и профиль требует восстановления.

Адаптер использует `ServerMaintenanceService(AppPaths, IVpsRemoteSessionFactory)` и `SshNetVpsSessionFactory` с шестиминутным лимитом выполнения, чтобы поддержать операции Let’s Encrypt и архивирования. Загрузка копии ограничена backend-контрактом 128 МиБ. Обновление 3x-ui только проверяется; установка обновления здесь не предусмотрена.

Проверки ViewModel запускаются отдельно: `dotnet run --project tests/MaintenanceChecks/MaintenanceChecks.csproj`. Все SSH-вызовы там идут через подставной сервис; существующая сборка UI smoke должна использовать только временную базу и не нажимать действия обслуживания.
